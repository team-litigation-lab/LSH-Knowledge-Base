## Fixed this week

**Bugs** — commit `1053866`.

- `src/util.js:62-96` — `autoformatBody` treated a ``` fence line as a block start but kept no state
  for the lines *between* fences, so aligned text inside a code block (`Name:  value`) was converted
  into a pipe table. Admin → Library maintenance → Autoformat existing articles writes its result
  straight to a live revision with no review (`src/index.js:679`, `makeLive`), so every published
  entry containing a code fence was being silently corrupted for all readers. Reproduced against the
  real function before the fix, and the loop now carries fenced content through verbatim.
- `src/util.js:63,71` — the same pass turned the indented continuation lines of a list item into a
  table, splitting one list into list / table / list; `public/js/md.js:69` folds those lines into the
  item's text. Only a line starting in column 0 may open a table now. A genuine column-0 table is
  still converted, and the pass is still idempotent — which the admin action's `for(;;)` loop
  depends on, so that is asserted.
- `public/js/md.js:19` — the relative-link branch matched `//host/path`, a protocol-relative URL. An
  entry body containing `[Payroll](//evil.example/login)` rendered as an internal link: no
  `rel="noopener noreferrer"` and no `https?:` allowlist check. The branch now requires a single
  leading slash.
- `src/index.js:275` — `getEntry` did `JSON.parse(rev.data)` with no null check. `createEntry`
  writes the entry row and its first revision as two separate statements (`src/index.js:390-402`,
  no `batch`), so a failure between them leaves an entry with no revision; its author still sees the
  card under `?status=mine`, and opening their own contribution threw a TypeError — a 500. It now
  404s like any other unavailable entry. (The underlying non-atomic write is under *Needs a
  decision* below.)

## Needs a decision

**1. KB sessions never re-check Portal revocation.** (medium, cross-repo — in both reports)
`src/db.js:146-169` (`getReader`) trusts the signed cookie for the full 12 hours
(`ADMIN_HOURS`/`PORTAL_READER_HOURS`, `src/index.js:10`). The Portal's own
`functions/_utils.js:137-168` re-reads `users.status` on *every* API call and 401s unless it is
exactly `Approved`. This repo holds the same `env.DB` binding (`wrangler.json:12`) and already
queries that table at sign-in (`src/index.js:142`), but never looks again. So revoking or suspending
a trainer in the Portal — or their logging out — does not end their Knowledge Base admin session:
for up to 12 hours they keep publish, delete, `/api/admin/export` and set-team-code rights on the
shared library. The site lock propagates; revocation does not. Either `getReader` re-checks
`users.status`, or the Portal exposes a revocation endpoint this Worker consults. The asymmetry may
well be deliberate, which is exactly why it is a decision.

**2. The 5 GB upload cap is advisory only.** (medium)
`src/files.js:71-80` — `startUpload` validates the client-declared `body.size` against `MAX_SIZE`
and returns a `parts` hint, but `putPart` only checks `1 <= n <= 10000` and `byteLength <= PART_SIZE`
— never against the declared size or the part count — and `finishUpload` accepts whatever parts are
listed, then overwrites `lib_files.size` with the real object size. A tenured VA can declare
`size: 1048576`, PUT 10 000 parts of 10 MB each, and complete a ~100 GB object in the shared
`lshtraining` R2 bucket. The `upload` rate limit (`src/files.js:54`) covers `start` only, not the
PUTs. Enforcing it changes what a user can do, and the right ceiling is a hosting-cost question.

**3. Entry and first revision are not written atomically.** (low)
`src/index.js:390-402` — the two INSERTs are separate statements, which is what produces the orphan
the `getEntry` fix above now handles gracefully. Writing both in one `db.batch` prevents the orphan
existing at all, rather than tolerating it. Left alone because changing how entries are created
touches the write path for every contribution.

**4. Library maintenance scans the whole table on every pass.** (medium)
`src/index.js:680` (and the identical `tidy-titles` at `:666`) selects every live revision's full
JSON, parses all of them, then acts on 12. `public/js/app.js:1104` calls it in a loop until
`remaining <= 0`, so the full scan runs ⌈N/12⌉ times, and `remaining` is computed from that same
full scan. At a few thousand entries this exceeds Worker memory or the D1 response limit, the action
500s, and it can never complete — while the client keeps hammering until the throw. The fix is an
`id > ?` cursor, which changes the `remaining` contract the client depends on.

**5. An unapproved entry creates a publicly visible collection.** (low–medium)
`src/index.js:349-355` — a tenured VA submitting a new entry with a typed `collection` gets an
immediate `INSERT INTO lib_collections … archived = 0`, before any review, never rolled back if the
entry is rejected or withdrawn. `library()` (`:182`) lists all unarchived collections regardless of
entry count and `public/js/app.js:402` renders them unfiltered in the Search page's collection
picker, so unreviewed user-supplied text appears in site navigation for every reader. (The home-page
category select does filter on count, so the exposure is the Search picker.) Gating or cleanup is a
moderation-policy call.

**6. A transient image-host error strands a row forever.** (low)
`src/index.js:977-1004` — `storeImage` marks `status='gone'` only on 404, 403 or a 2xx with a bad
content type; a 500, a 502 or a throw returns `null` and leaves the row `pending`. `copyImages`
selects `status='pending' LIMIT 15` with no offset, so repeating the action returns the same 15 rows,
`copied: 0`, and an unchanging `remaining` indefinitely. Reachable only by a direct admin API call —
`copy-images` and the five import actions have had no caller in `public/js/app.js` since the Admin
screen lost its import blocks. Wants a retry counter, or marking non-retryable failures.

**7. The default branch is a `claude/*` branch.** (low)
`.github/workflows/checks.yml:9` pushes on `[claude/brave-newton-xors2t, main]`, and `main` does not
exist in this repo — confirmed on GitHub: the default branch really is
`claude/brave-newton-xors2t`, the only repo in the org not defaulting to `main`. The workflow's own
header comment admits it ("or main if it's renamed"). Nothing is broken today, but push-triggered CI
depends on an agent-generated branch name: rename or delete that branch and pushes stop being
checked silently, with only `pull_request:` still firing. Renaming the default branch is a
repo-settings change, and it would need the workflow and both repos' docs updated with it.

**8. `wrangler.json:7` — `compatibility_date` is `2024-09-23`, about 25 months stale.** (low)
The Worker keeps 2024 runtime semantics and opts out of later defaults and fixes. Bumping it changes
runtime behaviour for a live site, so it wants a deploy test rather than a blind edit. The wrangler
major itself (v3, with `3.114.17` in the lockfile) is the same kind of call — note that
`package.json`, the lockfile and the workflow do *not* disagree, so there is no drift to fix, only
the age of the pinned major.

**9. `PORTAL_URL` falls back to the production Portal.** (low)
`src/index.js:12` defaults it to `https://cm-training-activity.pages.dev`, so a misconfigured or new
environment authenticates against the real production Portal instead of failing — which is why CI
must override it explicitly (`checks.yml:49,51`). Making it required is the safer behaviour but
would break the current dashboard-vars deployment model (`wrangler.json:4`, `keep_vars: true`), so
it is a deployment decision. By contrast `SESSION_SECRET` already fails loudly
(`src/util.js:124`) and `KB_CODE_LOGIN` already fails closed — both correct.

**10. The Blueprint engine has drifted; this repo runs the older copy.** (low)
`public/js/lsh-blueprint.js` (487 lines) vs the Training-Portal's `lsh-blueprint.js` (519) — a file
both repos document as "the same file on every LSH platform"
(`public/js/blueprint-content.js:2`). The Portal's copy loads IBM Plex Sans where this one loads
Inter, centres the slide body with `justify-content: safe center` where this one is top-aligned
(`safe` is the point: plain `center` strands overflow out of scroll reach), and vertically centres
each PDF points block via `TOP`/`BOTTOM`/`blockH()`/`mid()` where this one hardcodes `y = 142`. So
the same deck renders differently on the two sites and the Portal's layout fixes are absent here.
The conflict sweep judged this LOCAL-AND-SAFE — copy the Portal's file over wholesale, since the
config is injected per site. I did not do it: `tests/blueprint.cjs:52` asserts "fits its frame"
against *this* engine and passes, so the copy is a visual change to the live VA and admin decks that
should be looked at, not pushed on a Saturday morning. It is a one-file change whenever you want it.

**11. `npm run seed:local` is not re-runnable.** (low, test fixture)
The seeds use `CREATE TABLE IF NOT EXISTS` plus plain `INSERT`, so re-seeding an existing local
database fails with `UNIQUE constraint failed: kb_stats.article_ref`. CI always starts from fresh
state so it never shows there, but locally a second `seed:local` half-applies, and a test run against
that state produces failures that look like real regressions — I hit exactly this during validation
(the suite reported 50/52 and then a different 9 failures, all state pollution; 52/52 on fresh
state). `INSERT OR REPLACE`, or a documented `rm -rf .wrangler` step, would fix it. Not done because
changing test fixtures deserves its own look.

**12. Four symbols are exported but used only inside their own module.** (cosmetic)
`src/files.js:13` `PART_SIZE`, `:14` `MAX_SIZE`, `src/util.js:24` `isAllCaps`, `:28` `sentenceCase`.
Dropping the keyword is a one-word change with no callers to break, but it is churn in source files
for no behavioural gain, so I left it rather than widen this week's diff.

## Verified clean

  all 12 routes in `src/index.js` have a caller (plus the three prefix routes); all 15 files in
  `public/` are referenced; and no `scripts/` entry is a dead one-off — `tettra_convert.py`,
  `glossary_extra.py`, `glossary_us.py` and `dead_links.json` all looked like stale migrations and
  all four proved live, documented in README and read at runtime.
- **SQL injection: none.** Every template-literal interpolation in `src/db.js` and `src/index.js` is
  a `?`-placeholder list, a constant, or a whitelist lookup. `ftsQuery` restricts to `[\p{L}\p{N}]+`
  and quotes each word. Placeholder/bind arity checked on all six import INSERTs — all match.
- **XSS: none found.** `md.js` escapes before every transform; `img src`/`href`/`style` values
  cannot carry a raw quote; pasted content goes back through `md.js`, so `paste-format.js` cannot
  execute a `<script>`.
- **R2 object keys:** `safeName` strips `/` and `\`, so no path traversal.
- **Token handling:** a reader cookie pasted into `lshkb_admin` verifies but fails the `adm` check;
  a missing `SESSION_SECRET` yields 401, not open access.
- **Admin route gate** covers every `adminAction`, `exportAll` and `adminInfo`; no second entry point
  to `autoformat-body`, the imports or `purge`.
- **All four `wrangler.json` bindings are read** (`FILES`, `ASSETS`, `TRAINING_DB`, `DB`). No orphan
  binding; no `vars` block by design (`keep_vars: true` protects the dashboard-set ones).
- **Seed SQL still matches the schema** the code queries, column for column, including the one table
  `importLegacy` reads that the seed omits (`kb_votes`, created by `ensureSchema`).
- **No real credential committed.** The plaintext password in `tests/seed-accounts.sql` is a fixture
  that deliberately exercises the legacy plain-comparison branch at `src/util.js:135`; the rest are
  mock-server constants and a CI-only `SESSION_SECRET`.
- **jsPDF and pdfjs pins agree** across production and CI (4.2.1 and 3.11.174 respectively).
- **Open PRs: none.** CI green on the default branch.
- **`autoformatBody` idempotency** held across 500 000 fuzzed inputs in the bug sweep, and is
  re-asserted after this week's change.
